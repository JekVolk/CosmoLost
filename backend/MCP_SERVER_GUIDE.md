# 🚀 CosmoLost FastMCP Gateway: Повна Інструкція

Цей посібник містить повний опис серверного шлюзу **FastMCP (Model Context Protocol)** для проєкту CosmoLost: архітектуру, специфікацію всіх 10 інструментів, інструкції із запуску (Stdio та SSE), конфігурацію клієнтів (GitHub Copilot, Cursor, Claude Desktop), міграцію та запуск тестів.

---

## 🧭 1. Архітектура та Принципи

CosmoLost FastMCP Gateway надає прямий інтерфейс між зовнішніми нейромережами (Claude, GitHub Copilot, Cursor, Gemini) та реляційною базою даних на базі 8 таблиць `core.models`:

```
+-------------------------------------------------------------+
|    Зовнішній ШІ-агент (GitHub Copilot / Claude / Cursor)   |
+-------------------------------------------------------------+
                               |
                      [Протокол FastMCP]
                    (Stdio або SSE JSON-RPC)
                               v
+-------------------------------------------------------------+
|    CosmoLost FastMCP Service (backend/mcp/server.py)        |
+-------------------------------------------------------------+
                               |
                     [Django ORM / SQL]
                               v
+-------------------------------------------------------------+
|        PostgreSQL 16 / SQLite (8 Core Tables)               |
+-------------------------------------------------------------+
```

### Ключові принципи:
- **БЕЗ векторного RAG**: Жодних галюцинацій чи векторного наближення. Усі запити виконуються через строгий реляційний ORM.
- **Офіційні дані NASA PDS**: Верифіковані координати, NSSDCA каталожні номери та цитати.
- **Захист від перевантаження**: Обмеження вибірок `LIMIT`, захист від `ValueError` при нечислових параметрах, автоматична санітизація дефісів у статусах.
- **Нормалізовані координати**: Автоматичний перерахунок довготи планетоцентричних систем Марса (`0..360`) у стандартну картографічну сітку (`-180..180`).

## 🛠️ 2. Каталог 10 Серверних Інструментів (Tools)

### 1. `search_artifacts`
- **Опис**: Пошук обладнання на Місяці та Марсі з фільтрами за назвою, локацією, статусом, типом та пагінацією.
- **Параметри**:
  - `query` (str, опціонально): Текстовий запит (назва, кратер, причина деактивації).
  - `celestial_body` (str, опціонально): `moon` або `mars`.
  - `artifact_type` (str, опціонально): `ROVER`, `LANDER`, `RETRO_REFLECTOR`, `SAMPLE_TUBE` тощо.
  - `operational_status` (str, опціонально): `ACTIVE`, `PASSIVE_ACTIVE`, `DORMANT`, `DEACTIVATED`, `DESTROYED`.
  - `is_featured` (bool, default False): Тільки обрані об'єкти.
  - `limit` (int, default 20, max 100): Кількість елементів.
  - `offset` (int, default 0): Зміщення для пагінації.
- **Повертає**: Список об'єктів із `latitude`, `longitude`, `longitude_normalized`, назвою та місією.

### 2. `get_artifact_details`
- **Опис**: Повний верифікований технічний паспорт, координати, маса, причина зупинки, орієнтовна земна дата останнього контакту та художній монолог від першої особи.
- **Параметри**: `artifact_id` (str, обов'язковий, наприклад: `perseverance-rover`).
- **Повертає**: Словник із полями паспорта або `{'error': '...'}` при 404.

### 3. `get_mission_manifest`
- **Опис**: Маніфест усього обладнання, ступенів, інструментів та уламків, залишених на поверхні конкретною місією.
- **Параметри**: `mission_id` (str, обов'язковий, наприклад: `apollo-11`).
- **Повертає**: Загальну кількість обладнання та детальний список елементів.

### 4. `get_last_sol_chronology`
- **Опис**: Остання зафіксована телеметрія (потужність Wh, пиловий фактор tau, нахил, температура), сумарний пробіг (одометрія) та розрахункова земна дата за солом.
- **Параметри**: `artifact_id` (str, обов'язковий, наприклад: `perseverance-rover`).
- **Повертає**: Телеметричний пакет або повідомлення про відсутність вайпоінтів для пасивного об'єкта.

### 5. `get_science_discoveries`
- **Опис**: Список бортових інструментів та наукових відкриттів (з доступним поясненням для дітей та строгим науковим фактом PDS).
- **Параметри**: `artifact_id` (str, обов'язковий, наприклад: `perseverance-rover`).
- **Повертає**: Список відкриттів або помилку 404 при неіснуючому ID.

### 6. `get_verified_citations`
- **Опис**: Офіційний міжнародний ідентифікатор NSSDCA, динамічний копірайт космічного агентства (NASA, ESA тощо) та PDS-нода.
- **Параметри**: `artifact_id` (str, обов'язковий).
- **Повертає**: Бібліографічні атрибути та посилання на канонічний URL.

### 7. `get_3d_and_media_assets`
- **Опис**: Прямі посилання на інтерактивні 3D-моделі `.glb` та фотоархів NASA високої роздільної здатності з кодами PIA та копірайтами.
- **Параметри**: `artifact_id` (str, обов'язковий).
- **Повертає**: URL 3D-моделі та масив фотографій.

### 8. `list_active_passive_artifacts`
- **Опис**: Перелік обладнання, яке функціонує сьогодні без джерел живлення (кутові лазерні відбивачі, капсули зі зразками) з динамічним визначенням їхньої ролі.
- **Параметри**: `celestial_body` (str, опціонально).
- **Повертає**: Список пасивних артефактів із описом наукової функції.

### 9. `list_celestial_bodies` *(Новий навігаційний інструмент)*
- **Опис**: Огляд підтримуваних небесних тіл (Місяць, Марс) із радіусом, гравітацією, типом картографічної проекції та кількістю обладнання.
- **Параметри**: Немає.
- **Повертає**: Список планет і супутників у базі.

### 10. `list_missions` *(Новий навігаційний інструмент)*
- **Опис**: Каталог космічних місій із фільтрацією за агентством (NASA, ESA) або небесним тілом.
- **Параметри**: `agency` (str, опціонально), `celestial_body` (str, опціонально).
- **Повертає**: Перелік місій із датами запуску, посадки та кількістю апаратів.

## ⚙️ 3. Попереднє Налаштування Бази Даних

Перед першим запуском сервера застосуйте міграції та наповніть базу перевіреними даними NASA:

```powershell
cd backend

# Застосування міграцій Django
uv run python manage.py migrate

# Наповнення бази перевіреними об'єктами (Apollo 11, Perseverance, Opportunity, ExoMars тощо)
uv run python manage.py seed_mcp_data
```

## 🚀 4. Запуск Сервера FastMCP

### 4.1. Режим Stdio (За замовчуванням для Copilot, Cursor та Claude)
```powershell
cd backend
uv run python mcp/server.py
```
Сервер працює через стандартний ввід/вивід (stdin/stdout), приймаючи RPC-запити.

### 4.2. Режим Server-Sent Events (SSE) для мережевих клієнтів
```powershell
cd backend
# Запуск на порті 8005
uv run python mcp/server.py --sse --port 8005 --host 0.0.0.0
```
Або через змінні оточення:
```powershell
$env:MCP_TRANSPORT="sse"; $env:MCP_PORT="8005"; uv run python mcp/server.py
```
