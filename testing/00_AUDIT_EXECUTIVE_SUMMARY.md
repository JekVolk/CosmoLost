## 2. Що було заплановано vs Що реально реалізовано (Batch 1)

### 2.1. Серверний бекенд, База Даних та Адмінка
* **Заплановано у v1**:
  - Строге дотримання архітектурного правила: **строго 8 таблиць PostgreSQL** (`celestial_bodies`, `missions`, `artifacts`, `traverse_waypoints`, `scientific_discoveries`, `artifact_media`, `community_publications`, `users`).
  - Швидкий публічний Web Portal API (<50 мс) з підтримкою фільтрів, пошуку, сферичної кластеризації (<500 м) за формулою гаверсину та премодерації публікацій спільноти.
  - Desktop Editor API з видачею контентних SMM-рубрик, генерацією SEO-пакетів і графовим рушієм рекомендації наступної теми.
  - Адмін-панель Django Unfold з сучасним інтерфейсом, інлайнами та кнопками ручного запуску парсингу NASA.
* **Реалізовано на 100%**:
  - Усі 8 таблиць створено без зайвих розширень схеми.
  - Повний набір ендпоінтів Portal API (`/api/v1/portal/`) та дублюючих аліасів (`/api/web/`).
  - Алгоритм сферичної кластеризації на основі BFS та гаверсину з групуванням об'єктів на відстані $\le 500$ м.
  - Повний набір ендпоінтів Editor API (`/api/v1/editor/`) з 3 готовими SMM-рубриками та генератором зв'язування серійності контенту.
  - Django Unfold кастомізовано у темному стилі з 4 навігаційними групами та первинними кнопками запуску синхронізації.
  - **92 тести з 92 проходять успішно (100% pass rate)**.

### 2.2. Серверний ШІ-шлюз FastMCP
* **Заплановано у v1**:
  - 8 FastMCP інструментів для ШІ-агентів (Claude, Gemini, Cursor) з прямим доступом до бази даних без важкого векторного RAG.
  - Підтримка протоколів Stdio та SSE.
  - Захист від ін'єкцій та перевірка першоджерел (NASA PIA / PDS).
* **Реалізовано на 100% (Перевиконано)**:
  - Реалізовано **10 інструментів** (8 базових + 2 навігаційні: `list_celestial_bodies`, `list_missions`).
  - Підтримка Stdio та SSE з конфігурацією Nginx (`proxy_buffering off`).
  - Безпекова санітизація від нуль-байтів (`\x00`), рядкових бомб (>10 000 символів), переповнення пагінації та NaN/Inf у координатах.
  - Покриття 23 тестами, включаючи хакерські сценарії ін'єкцій.

### 2.3. Завантажувач даних NASA (Loader / Ingest Worker)
* **Заплановано у v1**:
  - Clean Architecture з шарами Clients $\to$ Mappers $\to$ DTOs $\to$ Repositories.
  - Багатотокенний пул NASA з ротацією на HTTP 429/403.
  - Дельта-оновлення на базі SHA-256 хешів у Redis/JSON для запобігання надлишковим запитам до БД.
  - Фоновий демон `python manage.py run_ingest --daemon --interval 3600`.
  - Офлайн fallback на випадок блекауту API NASA.
* **Реалізовано на 97%**:
  - Повна реалізація TokenPoolManager, SyncStateStore та DTO.
  - Вбудовані офлайн-сіди для Tier-1 апаратів Місяця та Марса (Apollo, Spirit, Opportunity, Perseverance, InSight).
  - Усі 18 тестів проходять успішно.
  - *Відкладено на Batch 2*: Розширення парсингу на другорядні місії (Surveyor, Luna) та Celery Beat контейнер.

### 2.4. Вебпортал 3D (Web Client)
* **Заплановано у v1**:
  - 3D-сфера планет (Місяць / Марс) на Three.js з тайлами NASA Treks WMTS або 2K текстурами.
  - Маркери артефактів на базі `THREE.InstancedMesh` (1–2 draw calls для 60 FPS).
  - Сферична кластеризація артефактів (<500 м) з круглими бейджами кількості `(5)` та анімацією spiderfying (розкриття «павутинкою») при наближенні.
  - Картка артефакту (Drawer) з 3D-переглядачем `.glb` моделей з NASA CDN, монологом «Щоденник останнього Сола» та науковими фактами.
  - Каталог артефактів із фільтрами за 10 типами обладнання та пошуком.
  - Розділ відео спільноти з переглядом 9:16 роликів та модалкою подання відео.
  - Стек: Chakra UI v3, архітектура FSD v2.1.
* **Реалізовано на 67.5%**:
  - 3D-сфера Three.js, текстури 2K, шейдер атмосфери Марса, плавна інерція, hover-тултіпи — **працюють відмінно**.
  - Каталог на 118 артефактів (82 Місяць, 36 Марс) з живим пошуком та фільтрами.
  - Досьє артефакту з монологами «Останній Сол», телеметрією та описом науки.
  - Галерея відео спільноти та модалка подання з валідацією та збереженням у LocalStorage/API.
* **Критичні розриви (Gaps to fix in Batch 2)**:
  - ❌ **Відсутній 3D GLB Viewer**: Моделі `.glb` не завантажуються, показується тільки статичне 2D фото.
  - ❌ **Відсутній `THREE.InstancedMesh`**: Маркери створюються як 800+ окремих об'єктів `THREE.Group`, що перевантажує Three.js сцени.
  - ❌ **Відсутнє динамічне розкриття кластерів (Spiderfying)**: Кластери статично розведені лініями без числових бейджів та розкриття по кліку.
  - ❌ **Chakra UI v3 не встановлено**: Використано 2 665 рядків кастомного `global.css`, що порушує проектне правило `fsd-rules.md`.
  - ❌ **Порушення FSD v2.1**: Відсутній шар `pages/` (сторінки лежать у `widgets/`), відсутні `index.ts`, виявлено імпорт із нижнього шару в верхній (`shared` $\to$ `entities`).
  - ❌ **Нуль тестів у веб-клієнті**.

### 2.5. Десктопна «Фабрика контенту» (Desktop Client)
* **Заплановано у v1**:
  - Спліт-редактор 9:16 (1080x1920) на базі Chakra UI v3.
  - Мертві зони (Safe Zones) для TikTok, YouTube Shorts, Reels (220px зверху, 420px знизу, 150px справа).
  - Слайдовий таймлайн (~40 сек) із 4 фазами: Хук, Наука, Драма, Loop CTA.
  - Слова-магніти (0–3с), фіксація причини вибору (`selection_reason`), багатосерійні космічні хроніки.
  - Кінетичні субтитри з неоновим виділенням слів (`#FFD700`).
  - Реактивний PNGTuber аватар із 4 емоціями (SHOCK, EXPERT, IDLE, HYPE) та ліпсинком за RMS амплітудою звуку.
  - Нодовий редактор пайплайну контенту на базі `@xyflow/react` (11 типів нод, валідація графа, евристичний оцінювач віральності).
  - Дистрибуція: автопостинг у YouTube Shorts, Telegram-канал та нативний експорт «Відкрити папку з файлом» з авто-копіюванням 3-рядкового SEO-опису.
  - Native Desktop MCP Server (JSON-RPC 2.0 stdio) на 16 інструментів із конфігурацією Claude / Antigravity в 1 клік.
  - Local-First збереження 7 локальних сутностей у `%APPDATA%/` через `tauri-plugin-store`.
  - FFmpeg Sidecar монтажний конвеєр з Pillow-box розмиттям 4:3 фото та сторожовим таймером Rust Watchdog (30–300с).
* **Реалізовано на 85.8%**:
  - Спліт-студія 9:16, Safe Zones, таймлайн, слова-магніти, багатосерійність, кінетичні субтитри — **повністю реалізовано у коді та покрито тестами**.
  - Нодовий граф `@xyflow/react` з оцінювачем хука, валідацією DAG та симуляцією виконання.
  - PNGTuber аватар з ліпсинком від звуку та зміною емоцій за таймлайном.
  - YouTube Shorts, Telegram Bot та нативний експорт через OS Explorer/Clipboard — **повністю готові**.
  - Desktop MCP Server на 16 інструментів протестовано через реальний процес `child_process.spawn`.
  - Суворе дотримання FSD v2.1 та збереження стану через `tauri-plugin-store`.
  - **24 тестові сьюти Vitest проходять успішно**.
* **Головний розрив для Batch 2**:
  - ⚠️ **Rust FFmpeg Sidecar & Watchdog**: Команда `render_video_ffmpeg` у `src-tauri/src/lib.rs` повертає імітований успішний результат замість реального запуску бінарника FFmpeg через `tokio::process::Command` (було тимчасово відкладено згідно з `plans/00_MASTER_PLAN.md`).
