# Нефункціональні Вимоги (NFR) (01_NFR.md)

> **Статус**: `APPROVED`  
> **Версія специфікації**: `v0.2.0`  
> **Стандарт**: ISO/IEC 25010 (System and Software Quality Requirements)

---

## 1. Бюджет ресурсів та системні вимоги

### 1.1. Серверний бекенд (Docker Compose Стек: Nginx + Django + Postgres + Redis + FastMCP)
* **Архітектура розгортання**: Виділений сервер із Docker Compose (домен `lihtar.org`).
* **Контейнери стеку**: `nginx`, `web-frontend`, `django-backend`, `fastmcp-service`, `postgres:16-alpine`, `redis`, `celery-worker`, `celery-beat`.
* **Розподілені блокування (Distributed Task Locks)**: Захист від подвійного запуску щогодинного завантажувача через `Redis Lock` (TTL 1800c).
* **Процесор (CPU)**: 2 vCPU ядра.
* **Оперативна пам'ять (RAM)**: 1–2 ГБ RAM (завдяки тому, що відеомонтаж повністю винесено на клієнтські ПК).
* **Дисковий простір**: 20–30 ГБ NVMe SSD.

### 1.2. Клієнтська машина («Фабрика контенту» Desktop)
* **Принцип Local-First**: Усі обчислення, синтез мови, ліпсінк, анімації та рендеринг FFmpeg відбуваються **виключно на клієнтському ПК**.
* **Кешування B-roll**: Усі фотографії та 3D-моделі NASA завантажуються клієнтом напряму і зберігаються в локальній папці `%APPDATA%/CosmoLost/projects/{id}/assets/`.
* **Процесор (CPU)**: 4 ядра x86_64 / ARM64 (Apple Silicon M1+ або Intel Core i5 / AMD Ryzen).
* **Оперативна пам'ять (RAM)**: Від 2 ГБ вільної пам'яті (рекомендовано 4–8 ГБ для плавної роботи FFmpeg).
* **Дисковий простір**: Від 20 ГБ вільного місця на диску для збереження згенерованих відеороликів `.mp4`.
* **Операційна система**: Windows 10/11, macOS 12+, Ubuntu 20.04+.

### 1.3. Фінансовий бюджет інфраструктури (Zero-Budget Architecture)
* **Вартість хостингу медіа**: **$0 / місяць**. Усі важкі 3D-моделі (.glb) та фотографії високої роздільності підтягуються клієнтами **напряму з відкритих серверів NASA** (`photojournal.jpl.nasa.gov`, `images-assets.nasa.gov`, `github/nasa-3d`), що усуває необхідність оренди дорогих S3/Cloudflare R2 сховищ.
* **Серверний хостинг**: розгортається на наявному сервері команди через Docker Compose без додаткових платних сервісів.

## 2. Продуктивність та масштабованість (Performance & SLA)

* **`NFR-PERF-01` (Час відгуку API)**: Ендпоінти `GET /api/v1/artifacts/` та `GET /api/v1/artifacts/:id/` зобов'язані віддавати відповідь швидше ніж за **150 мс** при $P_{95}$ завдяки кешуванню запитів.
* **`NFR-PERF-02` (Час локального рендерингу відео)**: Складання 30-секундного вертикального ролика 1080x1920 у FFmpeg на клієнтському ПК не повинно перевищувати **10–15 секунд** для сучасного 4-ядерного CPU.
* **`NFR-PERF-03` (3D Рендеринг на Вебпорталі)**: Інтерактивна мапа планет зобов'язана забезпечувати стабільні **60 FPS** на десктопних браузерах та не менше **30 FPS** на мобільних пристроях при відображенні до 2000 маркерів.
* **`NFR-PERF-04` (FastMCP Latency)**: Відповідь інструментів `search_artifacts` та `get_artifact_details` для підключених ШІ-агентів повинна становити менше **200 мс**.

---

## 3. Надійність та відмовостійкість (Reliability)

* **`NFR-REL-01` (Ізоляція від збоїв NASA)**: Вебпортал, FastMCP та десктопний застосунок працюють з локальної бази даних CosmoLost; недоступність або блокування серверів `api.nasa.gov` не зупиняє роботу користувачів екосистеми.
* **`NFR-REL-02` (Graceful Degradation для 3D)**: Якщо відеокарта користувача не підтримує WebGL2 — вебпортал плавно перемикається на 2D-карту або табличний каталог артефактів.
