# Скіл: Інженерний Алгоритм Комплексної Декомпозиції (`spec-decomposition-engine`)

> **Призначення**: Єдине централізоване ядро аналітичної декомпозиції.  
> Перетворює розмиті побажання та сирий текст у структуровані атомарні вузли специфікації з унікальними ID (`*[ID]`).

---

## 1. Головні правила декомпозиції

### 1.1. Закон «ТА / І» (Абсолютна атомарність дій)
Будь-яка вимога чи користувацький крок, де зустрічаються сполучники **«ТА»**, **«І»**, або перелік дій через кому, **зобов'язані** бути розщеплені на окремі незалежні операції `OP-*` над конкретними сутностями:
* *Помилка*: `Користувач оформлює замовлення і оплачує його карткою`.
* *Правильно (Атомарно)*:
  1. `OP-1: Створення замовлення` (Сутність: `ENT-Order`, Початковий стан: `Створено`).
  2. `OP-2: Ініціалізація платіжної сесії` (Сутність: `ENT-PaymentSession`).
  3. `HOOK-1: Вебхук підтвердження оплати` (Асинхронний тригер зміни стану замовлення на `Оплачено`).

### 1.2. Фільтр «НАВІЩО?» (Anti-Bloat Guard)
Перед створенням будь-якої сутності `ENT-*`, фічі `FEAT-*` чи операції `OP-*` аналізатор перевіряє:
1. **Навіщо це користувачу?** (Яку гостру біль це знімає?)
2. **Навіщо це проєкту зараз?** (Чи є це ядром MVP?)
3. **Що буде, якщо НЕ робити?** (Якщо "нічого критичного" — не робити в поточній версії).

## 2. Формула атомарної вимоги

$$\mathbf{[REQ\text{-}ID]} \mid \text{ДІЯ (Дієслово)} \mid \text{ОБ'ЄКТ (Сутність)} \mid \text{КОНТЕКСТ (Роль, Передумови)} \mid \text{ЗВ'ЯЗОК} (\ll\text{include}\gg \text{ / } \ll\text{extend}\gg)$$

### Правило `<<include>>` (Обов'язкова залежність)
Дія $A$ включає дію $B$ (`A <<include>> B`), якщо виконання $A$ неможливе без $B$:
* `Створити_профіль` $\xrightarrow{\ll include \gg}$ `Валідувати_email`.

### Правило `<<extend>>` (Умовне розширення)
Дія $B$ розширює дію $A$ (`A <<extend>> B [якщо УМОВА]`), якщо $B$ виконується тільки за настання певної умови:
* `Завершити_транзакцію` $\xrightarrow{\ll extend \gg}$ `Надіслати_SMS_квитанцію` [якщо увімкнено користувачем].
